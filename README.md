## 💡 About Me

I'm a full-stack engineer and AI/ML builder based in Bengaluru, currently pursuing my B.Tech in Computer Science at PES University. My work sits at the intersection of **generative AI, cloud-native architecture, and product engineering** — I design systems end-to-end, from data pipelines and model integration through to the interfaces people actually use.

I placed **1st nationally at the Google Gen AI Exchange Hackathon** (Google Cloud × Hack2Skill), competing against **270,000+ developers**, and hold a second 1st-place finish at **Inferentia 2.0**. My current focus is shipping production-grade GenAI products on Google Cloud — combining Vertex AI, Gemini, and Search Grounding with scalable Next.js/FastAPI architectures.

I care about systems that hold up outside a hackathon judging room — sensible architecture, real cost tradeoffs, and code that's still readable six months later.

- 🌱 **Currently exploring:** agentic AI workflows, multi-modal systems, system design fundamentals
- 💬 **Ask me about:** GenAI on GCP, Vertex AI / Gemini integration, full-stack architecture, building under hackathon time pressure

## 🚀 Featured Projects

<details>
<summary><strong>🥇 CareerLens — Personalized AI Career & Skills Advisor</strong></summary>
<br>

GenAI-powered career guidance platform built for the Google Cloud Gen AI Exchange Hackathon. Provides resume scoring, job matching, skill-gap analysis, and personalized learning paths using Vertex AI and Gemini — evaluated against 270,000+ developers nationwide and selected as the overall winner.

| Aspect | Details |
|:--|:--|
| **Stack** | Next.js, React.js, Node.js, Firebase, Firestore, Vertex AI, Gemini APIs, Firebase Auth |
| **Scale** | Evaluated by Google Cloud among 270,000+ developers and thousands of teams nationwide |
| **Performance** | Advanced through three competitive rounds — Top 100 → Top 10 → Winner |
| **Security** | Firebase Authentication with scoped Firestore security rules |
| **Impact** | 🥇 1st Place — Google Gen AI Exchange Hackathon · ₹2,00,000 prize |
| **Repository** | [github.com/BharathPESU/CareerLens](https://github.com/BharathPESU/CareerLens) |

CareerLens was architected to go beyond a single LLM call — resume scoring, job matching, and skill-gap analysis are handled as distinct stages, with Gemini orchestrating personalized output across each. The win came down to treating it like a real product: clean auth, structured data in Firestore, and a UI built to be demoed live under judging pressure.

</details>

<details>
<summary><strong>🥇 AgriSense — AI-Powered Smart Agriculture Platform</strong></summary>
<br>

An IoT and AI-based platform for real-time monitoring of soil moisture, temperature, crop health, and environmental conditions — combining sensor hardware with cloud ML for disease detection, irrigation automation, and price forecasting.

| Aspect | Details |
|:--|:--|
| **Stack** | Python (Flask), React.js, TypeScript, scikit-learn, GCP (BigQuery ML, Vision API, Earth Engine, Firebase), Raspberry Pi, ESP32, MQTT |
| **Scale** | Real-time multi-sensor ingestion pipeline feeding a live ML inference layer |
| **Performance** | Designed, built, and demoed within a 24-hour hackathon window |
| **Security** | Firebase-backed data layer with cloud-native access control |
| **Impact** | 🥇 1st Place — Inferentia 2.0 Hackathon · ₹75,000 prize |
| **Repository** | [github.com/BharathPESU/hackthon1](https://github.com/BharathPESU/hackthon1) |

The hardest part of AgriSense wasn't the ML — it was getting Raspberry Pi and ESP32 sensors to report reliably over MQTT into a pipeline that BigQuery ML and Vision API could actually consume in real time, end to end, in a single day.

</details>

<details>
<summary><strong>🔗 PeerLink — Offline Peer-to-Peer File Sharing & Messaging</strong></summary>
<br>

An Android application enabling fully offline peer-to-peer file sharing and real-time messaging over local Wi-Fi — zero internet required. Peers are auto-discovered via UDP broadcast, with file transfer handled over TCP using a multi-peer chunk-download strategy for speed.

| Aspect | Details |
|:--|:--|
| **Stack** | Kotlin, Android SDK, TCP/UDP Sockets, Kotlin Coroutines, SharedFlow, ViewModel, RecyclerView, Material UI |
| **Scale** | Fully offline, multi-peer chunked-transfer architecture |
| **Performance** | Parallel multi-peer chunk downloads for faster transfer speeds |
| **Security** | Local-network only — zero internet dependency, no external data exposure |
| **Impact** | Demonstrates systems-level networking design beyond typical web/app projects |
| **Repository** | [github.com/BharathPESU/PeerLink](https://github.com/BharathPESU/PeerLink) |

PeerLink was a deliberate move away from cloud-dependent apps — the interesting engineering problem was peer discovery and chunked transfer reliability on flaky local Wi-Fi, not the UI.

</details>

<details>
<summary><strong>🎓 KCET College Predictor — GenAI-Powered Admissions Platform</strong></summary>
<br>

A full-stack platform that helps students predict realistic college and branch options based on KCET rank, using live search-grounded AI rather than static cutoff tables. Deployed end-to-end on Google Cloud.

| Aspect | Details |
|:--|:--|
| **Stack** | FastAPI, Next.js 14, Tailwind CSS, shadcn/ui, Vertex AI (Gemini + Search Grounding), Firestore, Cloud Run, Firebase Hosting |
| **Scale** | Production GCP deployment with dedicated Firestore collections for cutoffs and feedback caching |
| **Performance** | Re-architected from a multi-agent LangGraph scraping pipeline to a Search-Grounded Gemini 2.0 Flash approach — dramatically smaller Docker images, simpler codebase, more reliable output |
| **Security** | Cloud Run with region-aware routing (asia-south1 / us-central1) for Search Grounding availability |
| **Impact** | End-to-end AI product — data pipeline design through production deployment with CI/CD via Cloud Build |
| **Repository** | *Private — available on request* |

This project's real lesson was knowing when to simplify: the original scraping-based multi-agent pipeline looked impressive on paper but was unreliable in practice. Replacing it with Gemini + Search Grounding traded some theoretical flexibility for something that actually worked in production.

</details>
